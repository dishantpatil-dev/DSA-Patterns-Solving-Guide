# Problem → Pattern Recognition Map

| Problem signal | First pattern to investigate |
|---|---|
| Sorted array + pair relation | Two pointers |
| Contiguous subarray/substring | Sliding window / prefix sum |
| Many range sums | Prefix sum |
| Many range updates | Difference array |
| Frequency / complement / membership | Hashing |
| Minimum X with monotonic feasibility | Binary search on answer |
| Middle/cycle in linked list | Fast & slow pointers |
| Reverse linked list | Pointer reversal |
| Matching nested symbols | Stack |
| Next greater/smaller | Monotonic stack |
| Minimum edges in unweighted graph | BFS |
| Tree levels / nearest nodes | BFS |
| Recursive subtree relationship | Tree DFS |
| Top K / repeatedly best current item | Heap |
| Dependencies / prerequisites | Topological sort |
| Connectivity under merges | DSU |
| Connect all nodes with minimum total edge weight | MST |
| Non-negative weighted shortest path | Dijkstra |
| Negative weighted edges | Bellman-Ford |
| Local choice with a proof | Greedy |
| Enumerate combinations/permutations | Backtracking |
| Repeated subproblems / state | DP |
| Split + solve + combine | Divide & conquer |
| Sorting makes relationships adjacent | Sort + scan/two pointers |

## Three-line pre-coding test

**Signal:** what in the statement matters?  
**Pattern:** what reusable technique matches it?  
**Invariant:** what remains true after each operation?

If you cannot write the invariant, slow down before coding.
